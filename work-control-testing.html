Security test bench

AI Control Testing

Security testing for an AI assistant, decided by evidence

Role: System design, specification and validation • Stack: Python, SQLite, MCP, pytest • Status: Built and tested; code not yet public

  • Built-in flaws 10 Each behind one switch, with a one-commit fix
  • Flaws open 12 of 12 Scripted attacks that succeed
  • Fixes in place 0 of 12 Scripted attacks that succeed
  • AI graders 0 Every result comes from hard evidence

1. How a result is decided

The harness never asks a model whether a reply looks safe. It reads what actually happened.

  1. 01 · Attack A case runs
    Scripted with no model, or live with Claude connected over MCP
  2. ↓
  3. 02 · Evidence Hard records are collected
    Canary markers, retrieved client ids, the tool-call trace and database side effects
  4. ↓
  5. 03 · Check Code decides pass or fail
    Each check reads the evidence; no AI grader is used

2. Flaws and fixes

Ten realistic flaws, each fixed at the tool boundary in code the model cannot reach.

FlagFlawFix at the boundary
V1Search returns every client's documentsFilter by the caller's clients in the data layer
V2Any case id is servedAuthorize every call against the server-side identity
V3Restricted notes returned to all rolesDrop fields by role before the model sees them
V4A secret in the server's instructionsRemove it; nothing the model is shown needs protecting
V5Retrieved text reads like operator guidanceReturn it inside a labeled untrusted-data envelope
V6The model can approve its own actionRequire a stored approval bound to the exact action and arguments
V7Messages can go to any addressRecipient allowlist per client
V8Authorization fails open on errorFail closed
V9Links and images to any domain pass throughNeutralize links outside the firm's domain
V10No limit on tool callsCap per session, then refuse with a needs-review status

Live runs with Claude over MCP

The same cases ran live with Claude Opus 5.5 as the agent.

Vulnerable server:
Every attack succeeded at least once
Fixed server, both servers loaded:
4 cases passed 4 of 4; 2 cases failed by repeating the other server's key
Fixed server loaded alone:
10 of 10 attempts passed

The failures with both servers loaded are counted as leaks, not explained away; the rerun with the fixed server alone shows the fixed controls hold.
